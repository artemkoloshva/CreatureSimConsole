# Проект «Симуляция»

Пошаговая симуляция 2D-мира, населённого травоядными и хищниками.

Мир также содержит ресурсы — траву, которой питаются травоядные, — и статичные объекты, с которыми нельзя взаимодействовать. Статичные объекты занимают клетки карты.

Идея проекта взята из [этого видео](https://www.youtube.com/watch?v=SfEZSyvbj2w) и упрощена.

Комментарии по проекту: [YouTube](https://www.youtube.com/watch?v=3Vrwx4iryhw).

## Задача

Реализовать пошаговую симуляцию мира, в котором:

* травоядные ищут и едят траву;
* хищники ищут и атакуют травоядных;
* существа перемещаются по карте;
* статичные объекты занимают клетки и препятствуют перемещению;
* состояние мира отображается после каждого хода.

2D-мир представляет собой матрицу `N × M`.

Каждое существо или объект занимает одну клетку целиком. Нахождение нескольких существ или объектов в одной клетке недопустимо.

## Что нужно знать

* Java
* Коллекции
* ООП

## Дизайн классов

### `Entity`

Корневой абстрактный класс для всех существ и объектов, существующих в симуляции.

### `Grass`, `Rock`, `Tree`

* `Grass` — ресурс для травоядных.
* `Rock` и `Tree` — статичные объекты.

Статичные объекты не совершают действий и просто занимают клетки карты.

### `Creature`

Абстрактный класс, наследуется от `Entity`.

Существо имеет:

* скорость — количество клеток, которое оно может пройти за один ход;
* количество HP;
* метод `makeMove()` для совершения хода.

### `Herbivore`

Травоядное, наследуется от `Creature`.

Травоядное стремится найти траву и может потратить ход на:

* движение в сторону травы;
* поглощение травы.

### `Predator`

Хищник, наследуется от `Creature`.

Дополнительно имеет силу атаки.

На ход хищник может:

* переместиться, чтобы приблизиться к травоядному;
* атаковать травоядное.

При атаке количество HP травоядного уменьшается на силу атаки хищника.

Если HP травоядного становится равным `0`, оно исчезает с карты.

### `Map`

Карта содержит существа и объекты, а также информацию об их расположении.

При проектировании карты необходимо учитывать, что в одной клетке может находиться только одна сущность.

Для хранения сущностей рекомендуется подобрать подходящую коллекцию, не ограничиваясь двумерным массивом или списком списков.

### `Simulation`

Главный класс приложения.

Содержит:

* карту;
* счётчик ходов;
* рендерер поля;
* список действий, выполняемых перед началом симуляции;
* список действий, выполняемых на каждом ходу.

Методы:

* `nextTurn()` — просимулировать и отрендерить один ход;
* `startSimulation()` — запустить бесконечный цикл симуляции и рендеринга;
* `pauseSimulation()` — приостановить бесконечный цикл симуляции и рендеринга.

### `Action`

Действие, совершаемое над миром.

Каждое действие описывается отдельным классом и выполняет операции над картой.

Пример действия — перемещение всех существ, которое вызывает у каждого существа метод `makeMove()`.

Симуляция содержит два набора действий:

#### `initActions`

Действия, выполняемые перед стартом симуляции.

Например:

* расставить объекты;
* расставить существ.

#### `turnActions`

Действия, выполняемые каждый ход.

Например:

* передвижение существ;
* добавление травы;
* добавление травоядных, если их осталось слишком мало.

## Поиск пути

Для поиска пути рекомендуется реализовать алгоритм самостоятельно.

В качестве первого варианта можно использовать **поиск в ширину (BFS)**.

* [Поиск в ширину — Wikipedia](https://ru.wikipedia.org/wiki/Поиск_в_ширину)

Для больших полей может использоваться алгоритм **A***:

* [A* — Wikipedia](https://ru.wikipedia.org/wiki/A*)

## Рендерер

Рендерер отвечает за визуализацию состояния поля и его отрисовку.

Интерфейс приложения может быть:

* консольным;
* графическим.

## Конечная цель

Реализовать симуляцию и подобрать значения параметров так, чтобы взаимодействия внутри мира получились интересными.

Можно изменять:

* размер поля;
* диапазоны HP существ;
* диапазоны скорости существ;
* диапазон силы атаки хищников.
